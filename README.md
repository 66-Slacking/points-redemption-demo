# 积分与数字商品兑换

一个可在本地运行的演示 Web App。用户注册登录后完成预置任务获得积分，再用积分兑换数字商品。`ebook`、`course`、`theme` 的兑换码由[题目提供的外部 API](https://digital-goods-api.vercel.app/)发放；外部调用只发生在服务端。项目使用 TypeScript、Express、PostgreSQL 和服务端生成的 HTML 表单，不涉及真实支付。

## 功能

- 注册、登录；按用户隔离积分、流水和兑换记录。
- 三个预置任务，每个用户对每项任务只能领取一次积分。
- 展示商品与积分价格；积分不足时不能兑换。
- 展示兑换状态和成功取得的兑换码；外部结果不确定时保留“处理中”，可按原业务编号查询并重试。

## 环境要求

- Node.js 20 或更新版本，npm。
- 可访问的 PostgreSQL 数据库。需要先创建一个空数据库，例如 `points_demo`。
- 真实发码需要招聘方发放的有效 API Key；没有 Key 时仍可体验注册、任务和积分页面，兑换操作会被拒绝且不会扣分。

## 启动

1. 在 PostgreSQL 中创建空数据库 `points_demo`。例如，使用具有建库权限的账号执行：

   ```sql
   CREATE DATABASE points_demo;
   ```

2. 将 `.env.example` 复制为 `.env`，填写 `DATABASE_URL`。真实兑换时还需填写 `DIGITAL_GOODS_API_KEY`。连接串中的密码如含 `@`、`:` 等特殊字符，应按 URL 规则编码。`.env` 已被 Git 忽略，API Key 不应提交到仓库或放进浏览器代码。

3. 在项目根目录运行：

   ```sh
   npm ci
   npm run setup
   npm run dev
   ```

4. 打开 <http://127.0.0.1:3000>。`npm run setup` 创建表并写入演示数据，可重复执行；它不会清空已有业务数据。`npm run dev` 编译 TypeScript 后启动网站，修改代码后需重启进程。

测试账号：`demo` / `demo12345`。也可在网页注册新账号。该账号只用于演示。

## 环境变量

| 变量 | 作用 |
| --- | --- |
| `DATABASE_URL` | 主数据库连接串，必填。 |
| `TEST_DATABASE_URL` | 独立测试数据库连接串，仅运行自动化测试时必填。 |
| `DIGITAL_GOODS_API_KEY` | 外部 API Key，真实兑换时必填。 |
| `DIGITAL_GOODS_API_BASE_URL` | 外部 API 根地址，默认指向题目服务；测试使用本地模拟服务。 |
| `PORT` | 网站监听端口，默认 `3000`。 |

## 运行测试

在 PostgreSQL 中再创建一个**独立的空数据库**，例如 `points_demo_test`，并在 `.env` 中设置 `TEST_DATABASE_URL`，然后执行：

```sh
npm run setup:test
npm test
```

测试使用本地模拟发码 API，不消耗题目服务的请求或发码额度。它验证重复领分、重复提交兑换、并发兑换时不超余额、用户数据隔离、发码成功但回复丢失后的恢复，以及商品不可用时只退一次分。测试用户使用随机名称，可重复运行。

## 关键设计与取舍

- 积分余额由 `ledger` 流水求和。任务领取、兑换扣分和确定失败后的退分都在 PostgreSQL 事务中处理；同一用户的积分操作先锁定该用户行，防止并发超额兑换。
- 每次兑换有唯一 `requestId`。重复提交同一表单沿用原订单；服务端重试外部 API 时也始终使用该编号。订单、领取记录和积分流水都有数据库唯一约束。
- 请求发码前先按 `requestId` 查询外部结果。超时、限流或服务错误时保持“处理中”，不把未收到回复当成未发码；外部明确返回 `422 PRODUCT_UNAVAILABLE` 才确认失败并退分。处理同一订单时使用 PostgreSQL 咨询锁。
- 页面由服务端生成，使用普通 HTML 表单，没有额外前端框架。密码以带随机盐的 `scrypt` 哈希存储；登录会话使用随机且带 `HttpOnly` 的 Cookie。

## 已完成范围与已知限制

已实现任务书中的基础业务要求。真实 API Key 不包含在仓库中；目前通过本地模拟 API 验证了发码及故障流程，真实发码需在获得有效 Key 后验证。外部故障后的查询／重试由用户在兑换详情页手动触发，并设短暂冷却时间。若 API Key 更换时仍有结果不明的旧订单，需要人工向发码方核对；程序不会用新 Key 盲目重发。
